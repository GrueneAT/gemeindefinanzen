Vergleich aus einem Dokument — die abgedruckte Vergleichsspalte als Basis

01Strategy

Strategy summary

The comparison tab gains a second origin for the base side — the comparison column the document already prints itself. No new calculation path: aggregiereDokument() already collects wert (column 1) and vergleich (column 2) in one pass, so the internal mode is a projection of the same map read on the other field.

Sentinel in a, not a second state field. BASIS_INTERN cannot collide — dokument_id is INTEGER PRIMARY KEY and ids are compared via String(...) throughout. { a: 5, modus: "intern" } would be two states for one thing.
Visibility decided on data, never on document type. An OH-CSV document carries the column name ("VA 2025") but no values — 3149 posts checked, ev/fv are 0 throughout. A type gate would silently produce 1016 rows "new" against a base of 0.
Without an explicit clone every delta becomes 0 — and no existing test fails. Rewriting aggB in place makes base and comparison the same object. Warning signs: wasserfall.von === wasserfall.nach, status.unveraendert === status.gesamt. Task 1 pins both.
The self-check must not run in internal mode. There aggA.wert is aggB.vergleich by construction — the check would report "Geprueft. Alle 1048 stimmen ueberein", a tautology that looks like proof. The engine returns { modus: "intern", ausloeser } instead.
Visibility and default selection belong in ONE step. With one document standardVergleich returns null and vergleich.js:136-137 reaches docs[docs.length - 2].id → undefined → TypeError in the now-visible tab.
A Voranschlag prints no difference at all. Its column 3 is the RA of two years prior. The internal mode still computes correctly there (base = previous year's VA), but verification against a printed difference exists only for NVA and RA — the tests must not expect it from a VA.
Empirically pinned, not assumed

The internal diff of the NVA 2026 (EHH) yields 1048 rows, status 32 new / 6 dropped / 122 changed / 888 unchanged, revenue +790,300, expense +502,200, net +288,100, waterfall 473,600 → 761,700 — and matches the printed "1. NVA" column row by row with 0 deviations (160 EHH / 178 FHH keys with movement).

03Decisions

Key decisions & options

Sentinel BASIS_INTERN in a chosen

Against a third field modus: "intern" or a: null. One state, one field: zustand.a and the #vgl-a select value stay a single source. null already means "nothing selected yet". Collision is structurally impossible — dokument_id is INTEGER PRIMARY KEY.

Data-based hatVergleichsspalte() chosen

Against a check on typ or on fassung === "OH-CSV". Decided by measurement, not judgement: an OH-CSV document is typ: "VA" with an empty column 2, the half-state is spelled "OH-CSV (nur EHH)", and fassung is not even present in DATA.dokumente. The honest test is whether ev/fv carry numbers — per household half.

D1 default lives in standardVergleich chosen

Against placing it in fuelleAuswahl(), where no js test would break. The data-layer location keeps the rule in one place (meta.default_vergleich) and unit-testable in Node; the price is three named tests to adjust. posten stays optional so callers without it keep today's behaviour.

The engine returns the trigger, the DOM module does not derive it chosen

kontrolle yields { modus: "intern", spalte, dokument, ausloeser }. The alternative — null plus the logic in vergleich.js — would put domain knowledge ("which document triggers the check") into the DOM layer. null is still returned where no relationship exists, which keeps the existing "control does not apply" test green.

Swap button disabled in internal mode chosen

Against repurposing it to "switch to the loaded base document". A button with two meanings is exactly the pattern vergleich.js:12-15 rejects for the document switcher. Left as-is, the sentinel would land in b and produce an empty view with no error message.

RA support admits a VA as base, not only an NVA judgement, not measurement

Where no NVA of that year exists the VA is the valid plan and is legitimate as a base; a deviation is the known version question the existing deviation text already carries. Marked MEDIUM confidence in the research — the fixtures illustrate it (191 EHH / 231 FHH deviating posts) but do not prove it.

Counting discrepancy in D2 left open, flagged in the docs open

CONTEXT.md D2 counts 138 posts / 16,083,400 EUR in one key space; the research counts each household half separately (191 / 9,211,600 EHH and 231 / 18,238,700 FHH). Direction and conclusion are identical. The decision is untouched — but whoever quotes the figure in docs/BROWSER-APP.md names the counting method with it.
