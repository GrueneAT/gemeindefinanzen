01Strategy

Two files change in production code. Everything else is verification.

Strategy summary

A pure markup + stylesheet change. Both visual pieces already exist as Design-System components the app loads over CDN, so nothing is hand-rolled — no new dependency, no build step, no JavaScript change.

The H1 carries Beta as plain text. “Gemeindebudget auswerten — Beta”. A single accessible text node, trivially assertable, no sizing or rotation edge cases next to a large heading.
The big hint is a DS warn-callout placed outside the document manager. An <aside class="gat-callout gat-callout--warn"> with a .gat-callout__lead, sitting after the hero and before #toast-box — a page-level sibling of <details id="doc-manager">, never a child of it.
Placement is the load-bearing decision, not a layout preference. aktualisiereDokVerwaltung() sets manager.open = anzahl === 0, so a hint inside the document manager would collapse out of view as soon as the first document loads. And @media print sets .doc-manager { display: none !important }, so it would vanish from printed reports too.
The old small paragraph is absorbed, not kept alongside. .app-beta-hinweis disappears from both the markup and the stylesheet. The small BETA Stoerer at the logo (.app-beta-marker) stays untouched — out of scope.
No test guards this area today, so the plan builds one. No existing spec asserts on the H1, the beta paragraph or any callout, and the repo has zero snapshot tests. One new spec asserts the rendered markup — including the print case with a control probe — and the full suite then runs as the regression net.
User decision at plan time

The acceptance criterion “funktioniert in beiden Farbmodi” is stale text. This app has exactly one colour mode — the high-contrast system was deliberately removed in commit bc1da4b, which also deleted tests/e2e/hc-toggle.spec.mjs. The AC is treated as satisfied by construction: use DS tokens, hard-code no colour, and do not resurrect the toggle.

02Flow

Tasks run in order; task N assumes 1..N-1 are done.

Task flow & dependencies

Task 1 H1 traegt Beta, DS-Callout ersetzt den kleinen Absatz web/index.html + web/css/app.css. The only production change in the whole plan — H1 suffix, new aside, old paragraph and its dead CSS gone. Verified by a standalone structural check script (placement, DS classes, contact link, print hide-list untouched, no new CSS, web/js untouched).
Task 2 Playwright-Spec fuer H1, Sichtbarkeit, Zuklapp-Fall und Druck tests/e2e/beta-hinweis.spec.mjs — four tests: H1 text; callout visible on open with contact and outside #doc-manager; still visible after a real fixture PDF collapses the manager; not hidden under print emulation, with #doc-manager as the control probe.
Task 3 Regressionsnetz — vollstaendige Suite gruen npm run test:e2e + npm run test:js, plus the untouched Python gates as a final sanity check. Fix causes, never weaken assertions.

03Decisions

Key decisions & options

Beta in the H1: plain text suffix chosen

Chosen: append “ — Beta” to the existing <h1 class="gat-headline gat-hero__title">.

Rejected: a second, large gat-stoerer--magenta badge next to the H1. Base .gat-stoerer sets no font-size, so next to a --gat-text-h1 heading it inherits a huge size and needs new local sizing/rotation CSS — the exact “Eigenbau” the issue’s Constraints forbid — and it reads as redundant next to the Stoerer already at the logo. .gat-tag--warn was rejected too: a 0.85rem status pill built for table cells is not “gross, nicht zu uebersehen”.

Callout placement: sibling before #doc-manager chosen

Chosen: after </header> of .gat-hero, before <div id="toast-box"> — above the document manager but strictly outside it.

Rejected: inside .doc-manager-body (“above the document list”). Two independently verified failures: the hint collapses when aktualisiereDokVerwaltung() closes the <details> on the first loaded document, and it disappears entirely in print. Both directly violate acceptance criteria.

Print: add nothing to the hide-list chosen

The callout prints by default because it is not in the app’s @media print hide-list, and the Design System already ships break-inside: avoid for every .gat-callout variant. Zero new print CSS. Hiding it was rejected: the AC forbids a printed report that omits the Beta disclosure (“aber auch nicht luegen”).

“Beide Farbmodi”: satisfied by construction resolved by user

The app has one colour mode; the high-contrast toggle was intentionally removed in bc1da4b. Resolution: use the DS --gat-web-callout-warn-* tokens as-is, hard-code no colour, add no prefers-color-scheme handling, and do not resurrect the toggle. The three chart themes only recolour ECharts canvases and never touch page-level callouts.

Verification without an existing safety net risk addressed

Nothing in the current suite would catch a regression here. The new spec asserts the rendered markup directly and uses #doc-manager as a control probe in the print test — without it, a broken emulateMedia call would let the print assertion pass vacuously. The document-manager test uses the real fixture PDF rather than faking the collapsed state.
